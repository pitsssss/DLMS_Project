## UC-01: Register Account
Use Case ID

## UC-01
Use Case Name
إنشاء حساب مواطن
Primary Actor
Citizen
Supporting Actors
OTP Service


<!-- Page 3 -->

Description
يسمح هذا االستخدام للمواطن بإنشاء حساب جديد في النظام باستخدام رقم الهاتف والبيانات األساسية، ليتمكن الحقاً من
استخدام خدمات رخص القيادة الرقمية.

Preconditions
ًيجب أال يكون رقم الهاتف مسجالً مسبقا.

ًيجب أال يكون الرقم الوطني مسجالً مسبقا.

يجب أن تكون خدمة OTP متاحة.

Trigger
يقوم المواطن بفتح التطبيق واختيار “إنشاء حساب جديد”.

Main Flow
يفتح المواطن شاشة إنشاء الحساب.

يُدخل رقم الهاتف.

يتحقق النظام من عدم وجود حساب سابق بنفس رقم الهاتف.

يرسل النظام رمز تحقق OTP إلى رقم الهاتف.

يُدخل المواطن رمز التحقق.

يتحقق النظام من صحة رمز OTP.

يُدخل المواطن البيانات األساسية المطلوبة.

يتحقق النظام من صحة البيانات المدخلة.

يقوم النظام بإنشاء الحساب.

يعرض النظام رسالة نجاح إنشاء الحساب.

Alternative Flows
A1:
رقم الهاتف مستخدم مسبقا
يعرض النظام رسالة تفيد بوجود حساب مرتبط بهذا الرقم.

A2: رمز OTP
غير صحيح
يعرض النظام رسالة خطأ ويطلب إعادة إدخال الرمز.

A3: انتهاء صالحية OTP

يطلب النظام إرسال رمز جديد.


<!-- Page 4 -->

A4:
الرقم الوطني مستخدم مسبقا
يمنع النظام إنشاء الحساب ويعرض رسالة مناسبة.

Postconditions
يتم إنشاء حساب مواطن فعال داخل النظام.

Business Rules
BR-01, BR-02

Main Flow
يفتح المستخدم شاشة تسجيل الدخول.

يُدخل رقم الهاتف أو اسم المستخدم وكلمة المرور.

يتحقق النظام من صحة بيانات الدخول.

يتحقق النظام من حالة الحساب.


<!-- Page 5 -->

يوجه النظام المستخدم إلى الواجهة المناسبة:

تطبيق المواطن
لوحة التحكم اإلدارية
Alternative Flows
A1:
كلمة المرور غير صحيحة
يعرض النظام رسالة خطأ.

A2:
الحساب غير فعال
يمنع النظام الدخول ويعرض سبب عدم التفعيل.

A3:
المستخدم ال يملك صالحية دخول لوحة التحكم
يمنع النظام الوصول إلى لوحة التحكم.

## UC-03: Complete Profile
Use Case ID

## UC-03
Use Case Name
إكمال الملف الشخصي
Primary Actor
Citizen
Description
يسمح هذا االستخدام للمواطن بإكمال بياناته الشخصية المطلوبة قبل استخدام الخدمات الحكومية داخل التطبيق.

Preconditions
يجب أن يكون المواطن مسجالً في النظام.


<!-- Page 6 -->

يجب أن يكون المواطن مسجل الدخول.

Trigger
يحاول المواطن تقديم خدمة تتطلب ملفاً شخصياً مكتمالً، أو يفتح شاشة الملف الشخصي.

Main Flow
يفتح المواطن شاشة الملف الشخصي.

يعرض النظام البيانات المطلوبة.

يُدخل المواطن البيانات الشخصية:

االسم الكامل
الرقم الوطني
تاريخ الميالد
المحافظة
العنوان
رقم الهاتف
يتحقق النظام من صحة البيانات.

يحفظ النظام البيانات.

يغير النظام حالة الملف الشخصي إلى “مكتمل”.

يعرض النظام رسالة نجاح.

Alternative Flows
A1:
بيانات ناقصة
يطلب النظام استكمال الحقول المطلوبة.

A2:
الرقم الوطني غير صالح
يعرض النظام رسالة خطأ.

A3:
بيانات مكررة
يمنع النظام حفظ البيانات إذا كانت مرتبطة بحساب آخر.

Postconditions
يصبح ملف المواطن الشخصي مكتمالً وقابالً الستخدام الخدمات.

## UC-04: Submit New License Application
Use Case ID

## UC-04
Use Case Name
تقديم طلب إصدار رخصة جديدة
Primary Actor
Citizen
Supporting Actors
Notification Service
Description
يسمح هذا االستخدام للمواطن بتقديم طلب إصدار رخصة قيادة جديدة من خالل اختيار نوع الرخصة وبدء مسار الطلب حسب
القواعد المحددة في النظام.

Preconditions
يجب أن يكون المواطن مسجل الدخول.

ًيجب أن يكون الملف الشخصي مكتمال.

يجب أال يكون لدى المواطن طلب نشط لنفس نوع الرخصة.

يجب أن يحقق المواطن شروط األهلية الخاصة بنوع الرخصة.

Trigger
يختار المواطن خدمة “إصدار رخصة جديدة”.

Main Flow
يفتح المواطن قائمة الخدمات.

يختار خدمة إصدار رخصة جديدة.

يختار نوع الرخصة المطلوبة.


<!-- Page 8 -->

يتحقق النظام من شروط األهلية.

يتحقق النظام من عدم وجود طلب نشط مشابه.

يعرض النظام المتطلبات والوثائق المطلوبة.

ينشئ النظام طلباً جديداً بحالة مبدئية.

يطلب النظام من المواطن رفع المرفقات المطلوبة.

بعد اكتمال المرفقات، ينتقل الطلب إلى حالة “بانتظار مراجعة المرفقات”.

يرسل النظام إشعاراً للموظف بوجود طلب جديد.

يعرض النظام رقم الطلب للمواطن.

Alternative Flows
A1: المواطن غير مؤهل
يعرض النظام سبب عدم األهلية، مثل عدم تحقق شرط العمر.

A2:
يوجد طلب نشط مشابه
يمنع النظام إنشاء طلب جديد ويعرض الطلب الحالي.

A3: الملف الشخصي غير مكتمل
يوجه النظام المواطن إلى إكمال الملف الشخصي.

Postconditions
يتم إنشاء طلب إصدار رخصة جديد مرتبط بالمواطن.

Business Rules
BR-02, BR-03, BR-04, BR-05, BR-06, BR-41, BR-42

## UC-05: Upload Required Documents
Use Case ID

## UC-05
Use Case Name
رفع المرفقات المطلوبة
Primary Actor
Citizen

<!-- Page 9 -->

Description
يسمح هذا االستخدام للمواطن برفع الوثائق المطلوبة ألي خدمة، مثل إصدار رخصة، تجديد رخصة، بدل فاقد، بدل تالف، أو
فك حجز.

Preconditions
يجب أن يكون هناك طلب فعال.

يجب أن تكون قائمة المرفقات المطلوبة معرفة في النظام.

يجب أن يكون المواطن مالك الطلب.

Trigger
يفتح المواطن صفحة مرفقات الطلب.

Main Flow
يعرض النظام قائمة المرفقات المطلوبة.

يختار المواطن نوع المرفق.

يرفع الملف المطلوب.

يتحقق النظام من صيغة الملف وحجمه.

يحفظ النظام المرفق.

يغير النظام حالة المرفق إلى “بانتظار المراجعة”.

يعرض النظام حالة كل مرفق.

Alternative Flows
A1:
صيغة الملف غير مدعومة
يرفض النظام الملف ويعرض الصيغ المقبولة.

A2:
حجم الملف كبير
يرفض النظام الملف ويعرض الحد األقصى للحجم.

A3:
إعادة رفع مرفق مرفوض
يسمح النظام باستبدال المرفق القديم بمرفق جديد.

Postconditions
يتم حفظ المرفقات وربطها بالطلب.

## UC-06: Review Documents
Use Case ID

## UC-06
Use Case Name
مراجعة المرفقات
Primary Actor
Employee
Required Permission
Review Documents
Supporting Actors
Notification Service
Description
يسمح هذا االستخدام للموظف المخول بمراجعة مرفقات الطلب وقبولها أو رفضها مع توضيح السبب عند الرفض.

Preconditions
يجب أن يكون الطلب بحالة “بانتظار مراجعة المرفقات”.

يجب أن يمتلك الموظف صالحية مراجعة المرفقات.

Trigger
يفتح الموظف قائمة الطلبات التي تحتاج إلى مراجعة مرفقات.

Main Flow
يفتح الموظف لوحة التحكم.

يعرض النظام الطلبات التي تحتاج مراجعة مرفقات.

ًيختار الموظف طلباً معينا.

يعرض النظام بيانات الطلب والمرفقات.


<!-- Page 11 -->

يراجع الموظف كل مرفق.

يقبل الموظف المرفقات الصحيحة.

إذا كانت جميع المرفقات مقبولة، ينقل النظام الطلب إلى مرحلة الدفع.

يسجل النظام العملية في سجل التدقيق.

يرسل النظام إشعاراً للمواطن.

Alternative Flows
A1:
مرفق غير صحيح
يرفض الموظف المرفق مع إدخال سبب الرفض.

A2: مرفق غير واضح
يطلب الموظف إعادة رفع المرفق.

A3: الموظف ال يملك الصالحية
يرفض النظام العملية.

Postconditions
إما أن ينتقل الطلب إلى مرحلة الدفع، أو يعود إلى المواطن لتصحيح المرفقات.

Business Rules
BR-08, BR-09, BR-30, BR-32, BR-43, BR-48

## UC-07: Pay Fees
Use Case ID

## UC-07
Use Case Name
دفع الرسوم
Primary Actor
Citizen
Supporting Actors
Payment Gateway, Notification Service
Description

<!-- Page 12 -->

يسمح هذا االستخدام للمواطن بدفع الرسوم المرتبطة بالطلبات أو االختبارات أو الغرامات أو التجديد.

Preconditions
يجب أن يكون هناك طلب أو غرامة بحاجة إلى دفع.

يجب أن تكون قيمة الرسوم محسوبة من النظام.

ًيجب أال تكون الرسوم مدفوعة مسبقا.

Trigger
يضغط المواطن على زر “دفع الرسوم”.

Main Flow
يعرض النظام قيمة الرسوم المطلوبة.

يختار المواطن طريقة الدفع.

يرسل النظام طلب الدفع إلى بوابة الدفع.

يقوم المواطن بإتمام عملية الدفع.

تعيد بوابة الدفع نتيجة العملية للنظام.

يتحقق النظام من نجاح الدفع وقيمة المبلغ.

يسجل النظام عملية الدفع.

يغير النظام حالة الطلب إلى المرحلة المناسبة.

يرسل النظام إشعار نجاح الدفع للمواطن.

Alternative Flows
A1:
فشل الدفع
يبقى الطلب بحالة “بانتظار الدفع”.

A2:
انقطاع االتصال مع بوابة الدفع
يحفظ النظام العملية بحالة “قيد التحقق”.

A3: محاولة دفع مكرر
ًيمنع النظام العملية إذا كانت الرسوم مدفوعة مسبقا.

A4: قيمة الدفع غير مطابقة
يرفض النظام اعتماد الدفع ويطلب التحقق.


<!-- Page 13 -->

Postconditions
يتم تسجيل عملية دفع ناجحة وربطها بالطلب أو الغرامة.

Business Rules
BR-10, BR-11, BR-12, BR-37, BR-45, BR-52
